# Новый слайс в features/

Повторяется на каждой части оболочки: `projects`, `inspector`, `history`, `export`.
Структура одинаковая, и забывается всегда одно и то же — не сложное, а подключение.

Слайс — это вертикальный кусок функциональности: своё состояние, своя разметка,
свои утилиты. Наружу он показывает несколько имён и прячет всё остальное.

## Перед началом

| Файл | Что оттуда нужно |
|---|---|
| `docs/SPEC.md`, раздел 8 | какие слайсы вообще предусмотрены и чьи они |
| `docs/SPEC.md`, раздел 2 | границы зон A и B |
| `src/shared/store/board.ts` | что уже есть в общем сторе, чтобы не дублировать |

Слайс из зоны A (`features/canvas/*`) этой процедурой **не заводится** — там
свои правила, смотри скилл `canvas-node-type`.

## Шаг 1. Структура папки

```
src/features/<слайс>/
  index.ts        — единственная дверь наружу
  ui/             — компоненты
  model/          — состояние: срез стора, селекторы, типы слайса
  lib/            — чистые функции без React и без стора
```

Пустые папки не создавай. Нужен пока только `model/` — заведи `index.ts` и `model/`,
остальное появится, когда появится содержимое. Каталог с одним пустым файлом внутри
хуже, чем отсутствующий каталог: он выглядит как забытая работа.

`lib/` держи чистым — функции без импортов React и стора. Это то, что потом
тестируется без всякого окружения и переживает переписывание интерфейса.

## Шаг 2. Срез стора

Файл: `src/features/<слайс>/model/store.ts`.

Отдельный `create<...>()` на слайс, **не расширение `shared/store/board.ts`**.
Общий стор — контракт между зонами, он правится вдвоём коммитом `contract:`.
Слайсу почти никогда не нужно там место: своё состояние живёт у себя.

**Действия именуются глаголом**, в повелительном наклонении, от лица вызывающего:

| Так | Не так | Почему |
|---|---|---|
| `openCreate()` | `createDialogOpen` | действие, а не флаг |
| `renameProject(id, name)` | `setProjectName(...)` | `set*` описывает поле, глагол — намерение |
| `undo()` / `redo()` | `historyBack` | читается как предложение в коде вызова |
| `exportPng(options)` | `pngExport` | глагол первым, всегда |

Состояние — существительные, действия — глаголы. Правило одно и без исключений:
`store.doSomething()` должно читаться вслух как то, что происходит.

Пример живого среза — `src/features/projects/dialogsStore.ts`. Смотри там на
именование действий, но не на размещение: `projects` заводился до этой процедуры
и лежит плоско, без `model/`. Новые слайсы делай по структуре из шага 1.

## Шаг 3. Публичный index.ts

Наружу торчит **только то, что перечислено в `index.ts`**. Всё остальное —
внутренности слайса, и их можно переписывать, не спрашивая никого.

```ts
// src/features/history/index.ts
export { HistoryButtons } from './ui/HistoryButtons';
export { useHistory } from './model/store';
export type { HistoryEntry } from './model/types';
```

Два правила, оба нарушаются одинаково легко:

1. **Не делай `export *`.** Он утаскивает наружу всё, что случайно оказалось
   экспортированным внутри, и граница слайса перестаёт существовать молча.
2. **Чужой код импортирует `@/features/<слайс>`, а не файл внутри.** Появился
   импорт `@/features/history/model/store` из другого слайса — значит `index.ts`
   чего-то не отдаёт. Дополни `index.ts`, а не углубляйся в чужие потроха.

Внутри самого слайса ходить по файлам напрямую — нормально и правильно:
`./model/store`, `../lib/format`. Через собственный `index.ts` не ходи, получишь цикл.

## Шаг 4. Тест хотя бы на одно действие

Файл: `src/features/<слайс>/model/store.test.ts`.

Одно действие, но настоящее — то, где есть логика, а не присваивание. Тест на
`set({open: true})` не проверяет ничего.

```ts
import { beforeEach, expect, test } from 'vitest';
import { useHistory } from './store';

beforeEach(() => useHistory.setState(useHistory.getInitialState()));

test('undo возвращает предыдущее состояние и двигает указатель', () => {
  const { push, undo } = useHistory.getState();
  push({ label: 'первый' });
  push({ label: 'второй' });

  undo();

  expect(useHistory.getState().current?.label).toBe('первый');
});
```

Два момента, на которых спотыкаются:

- **Стор глобальный, тесты его делят.** Без сброса в `beforeEach` тесты начнут
  зависеть от порядка запуска — и падать по одному при полном прогоне, проходя
  поодиночке.
- **`getState()` — снимок.** Действия из него звать можно, а вот читать
  результат надо свежим `useHistory.getState()`, иначе увидишь состояние
  до изменения. Это ловушка, на которую легко потратить полчаса.

Всё, что попало в `lib/`, тестируется обычными юнит-тестами без окружения —
там React не нужен.

## Шаг 5. Граница зон — проверяется машиной

Слайс зоны B **не импортирует ничего из `features/canvas`**. Общее место —
`shared/types` и `shared/store`, и они правятся вдвоём коммитом `contract:`.

Эту проверку не надо помнить: она в `biome.json`, правило
`style/noRestrictedImports` с областью `src/features/**` кроме `src/features/canvas/**`.
Ловит все четыре формы, включая относительные пути:

```
@/features/canvas/engine/CanvasStage      → заблокировано
../canvas/engine/viewport                 → заблокировано
../../canvas/engine/viewport              → заблокировано
../../features/canvas/engine/viewport     → заблокировано
```

Запускается сама:

```bash
npm run lint
```

Хук `gate-stop.sh` гоняет `lint` на завершении сессии, поэтому нарушение
не доедет до коммита даже если про него забыть.

**Если правило сработало — это не повод его обходить.** Оно означает ровно одно:
слайсу понадобилось то, чего нет в общем контракте. Порядок действий такой:

1. Проверь, решается ли это через `shared/store` — обычно да.
2. Не решается — заведи запрос в `docs/CONTRACT-REQUESTS.md`: что нужно,
   какая сигнатура, зачем.
3. Дождись напарника. Правка контракта — коммит `contract:` вдвоём.

Чего **не** делать: добавлять `// biome-ignore` на этот импорт, расширять
`overrides` в `biome.json`, переписывать импорт так, чтобы шаблон его не увидел.
Правило написано ровно против этого — тихого расползания зон.

## Шаг 6. Подключение — то самое, что забывается

Слайс написан, тесты зелёные, а на экране ничего нет. Каждый раз одно и то же:

- **Маршрут или родительский экран не знает о слайсе.** Компонент из `index.ts`
  вставлен в `src/app/router.tsx` или в нужный экран? Без этого он существует
  только в файловой системе.
- **Экран есть, данных нет.** Слайс, который читает IndexedDB, обязан
  перечитываться при изменениях извне — иначе изменения видны только после F5.
  Образец — счётчик `revision` в `features/projects/dialogsStore.ts`.
- **Действия объявлены, но не вызываются.** Кнопка есть, `onClick` нет.

## Готово, когда

- [ ] папка с `index.ts` и `model/`, пустых каталогов не наплодено
- [ ] срез стора отдельный, `shared/store/board.ts` не тронут
- [ ] действия названы глаголами, состояние — существительными
- [ ] `index.ts` перечисляет экспорты поимённо, без `export *`
- [ ] снаружи слайс импортируется как `@/features/<слайс>`, без пути внутрь
- [ ] тест на действие с логикой, со сбросом стора в `beforeEach`
- [ ] `npm run lint` зелёный — значит граница зон не нарушена
- [ ] `npm run typecheck` и `npm test` зелёные
- [ ] слайс подключён к маршруту или экрану и виден глазами
