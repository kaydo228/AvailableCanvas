# Журнал сессий

Дословные промпты обоих участников, по папке на человека. Пишется автоматически
хуком `UserPromptSubmit` (`.claude/hooks/log-prompt.sh`) — руками сюда ничего
не добавляется.

| Папка | Кто | Зона |
|---|---|---|
| `roman/` | roman_restov | движок холста: вид, жесты, сетка, узлы |
| `alfis/` | alfis | оболочка: обвязка, проекты, хранение, инспектор, клавиши |

## Настройка на новой машине

Хук ищет имя цепочкой и в переменную окружения больше не упирается:

1. `DEV_NAME`, если она есть в окружении процесса;
2. файл `.claude/dev-name` в проекте — **рекомендуемый способ**;
3. `git config user.name`;
4. иначе `unknown/`.

Самый надёжный вариант — файл, он читается в момент вызова:

```bash
echo '<ваше имя>' > .claude/dev-name
```

Файл в `.gitignore`, у каждого свой.

**Почему не переменная окружения.** Процесс Claude Code забирает окружение
при старте. Правка `~/.zshrc` или `~/.zshenv` до него не доходит, пока
не перезапустишь — а записи всё это время молча уходят в `unknown/`.
Так случилось дважды за 25 августа: первый раз журналы обоих участников
слились в одну папку и конфликтнули при merge, второй раз переменная была
выставлена, проверена в терминале — и всё равно не действовала в хуке.

Проверить, что хук резолвит имя правильно:

```bash
echo '{"prompt":"проверка"}' | CLAUDE_PROJECT_DIR="$PWD" bash .claude/hooks/log-prompt.sh
```
