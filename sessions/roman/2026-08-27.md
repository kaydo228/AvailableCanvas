# План починки

## Развилка, которую надо решить до кода

**Чинить или отказывать?** Два входа документа ведут себя по-разному:

- **Импорт файла** — чужие данные, отказ допустим и уже так работает.
- **Чтение из IndexedDB** — данные пользователя, и часть из них **уже испорчена** сегодняшним багом. Отказ здесь = «твоя доска больше не открывается».

Предлагаю: **чинить всё, что чинится однозначно, и говорить об этом; отказывать только там, где починка была бы гаданием.** Один и тот же код на обоих входах — тогда чтение из базы задним числом лечит доски, испорченные до фикса.

| Нарушение | Решение | Почему |
|---|---|---|
| `zoom` вне `[0.1, 4]` | зажать | однозначно |
| дубли в `order` | оставить первое вхождение | однозначно |
| id в `order` без узла | выкинуть из `order` | уже так делает `removeNode` |
| узел без записи в `order` | дописать в конец | однозначно |
| `opacity` вне `[0, 1]` | зажать | однозначно |
| `width`/`height` ≤ 0 или не конечные | к `1` | однозначно |
| `x`/`y`/`rotation` не конечные | к `0` | однозначно |
| `Endpoint` с `nodeId` **и** `point` | оставить `nodeId` | привязка сильнее координаты |
| `Endpoint` пустой `{}` | к `point: {x:0, y:0}` | иначе линию не нарисовать |
| `Endpoint.nodeId` в несуществующий узел | отвязать в `point` через `operations.removeNode` | инвариант 4 уже это умеет |
| `group.children` с чужими id | выкинуть лишние | однозначно |
| ключ в `nodes` ≠ `node.id` | **отказ** | неясно, что правда — ключ или поле |
| `schemaVersion` чужой | **отказ** | уже так работает |

Починку на импорте показывать тостом: «Доска открыта, но 3 места пришлось поправить: …». Молча чинить чужой файл нельзя — человек должен знать, что получил не то, что отдавали.
