# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Prostor — бесконечная доска для диаграмм, заметок и изображений. Бэкенда нет,
данные живут в браузере. ТЗ: [docs/SPEC.md](docs/SPEC.md).

## Команды

| Команда | Что делает |
|---|---|
| `npm run dev` | Vite на <http://localhost:5173> |
| `npm run build` | `tsc --noEmit` + сборка |
| `npm test` | Vitest, один прогон |
| `npm run test:watch` | Vitest в watch |
| `npm run e2e` | Playwright, сам поднимает dev-сервер (без замера) |
| `npm run perf` | замер NFR-01, отдельный проект Playwright в один поток |
| `npm run typecheck` | только типы |
| `npm run lint` | Biome — линтер и форматтер сразу |

Один файл тестов: `npx vitest run src/features/canvas/engine/grid.test.ts`.
Один тест по имени: `npx vitest run -t 'ловит дубль в order'`.
Один сценарий Playwright: `npx playwright test e2e/smoke.spec.ts`.
Починить формат и импорты: `npx biome check . --write`.

Vitest берёт только `src/**/*.test.{ts,tsx}` — `e2e/` принадлежит Playwright,
у него свой раннер.

## Разделение зон — главное правило

Два разработчика, два непересекающихся слоя. **Свою зону не покидать.**

| | A — «Движок» | B — «Оболочка» |
|---|---|---|
| Зона | всё, что рисуется на холсте | всё, что вокруг холста |
| Модули | `features/canvas/{engine,nodes,tools,selection,connectors}` | `features/{projects,inspector,history,persistence,export}`, `shared/ui` |
| Не трогает | ничего вне `features/canvas` | ничего внутри `features/canvas` |

Перед правкой файла проверь, в чьей он зоне. Если задача требует чужой зоны —
не лезь туда, а запиши запрос в [docs/CONTRACT-REQUESTS.md](docs/CONTRACT-REQUESTS.md).

## Контракт между зонами

`src/shared/types/document.ts` (модель данных) и `src/shared/store/` (действия над
документом) — общий шов. **Меняются только парой, коммит с префиксом `contract:`.**
Не расширяй их в одиночку, даже если очень удобно: разъедется у обоих.

B вызывает действия стора, A их исполняет и рисует. `useBoardStore` — плоский
Zustand-стор поверх Immer, сгруппирован по секциям: документ, узлы, порядок слоёв,
группы, коннекторы, выделение, инструменты, вид.

## Инварианты модели

Ломать нельзя, они закреплены тестами в `src/shared/model/invariants.test.ts`:

1. Каждый `id` из `order` есть в `nodes` и наоборот — соответствие взаимно однозначное.
2. `ConnectorNode` не участвует в `groupId`.
3. У `Endpoint` задан **ровно один** из `nodeId` или `point` — никогда оба и никогда ни одного.
4. Удаление узла обязано отвязать все ссылающиеся на него `Endpoint`, подставив им
   последние вычисленные координаты в `point`.
5. `zoom` всегда в диапазоне `[0.1, 4]`.

**Инвариант 4 реализован** в `src/shared/model/operations.ts` — удаление
узла отвязывает концы коннекторов, считая координаты до удаления.

Остальные четыре держатся **конструкцией кода**, а не проверками: инвариант 1 —
`addNode` пишет и в `nodes`, и в `order`; инвариант 3 — конструкторы
`pointEndpoint` и `nodeEndpoint` в `canvas/connectors/geometry.ts`, собрать
неправильный конец через них нельзя; инвариант 5 — `clampZoom` в движке.

**Валидатор реализован** (27.08): `src/shared/model/invariants.ts` находит
нарушения и не чинит их, `validateDocument` собирает все правила разом.
Границы зума берёт из `ZOOM_MIN`/`ZOOM_MAX` в модели, а не повторяет числами.

Починка — отдельно, в `src/features/persistence/repair.ts` (зона B): она
зовётся и на импорте файла, и на чтении из IndexedDB, поэтому открытие доски
задним числом лечит документы, испорченные до этого. Раньше документ попадал
в стор без единой проверки, и через это были достижимы битые данные —
см. `docs/nightly/connectors/08-аудит-ломатель.md` и
`docs/nightly/shell/01-план-починки.md`.

Не удаляй тесты, чтобы они позеленели.

## Рендер холста — запрещённые альтернативы

- **Рендер только через `react-konva`.** DOM- и SVG-узлы на холсте не создавать.
  Единственное исключение — оверлей `<textarea>` для редактирования текста
  (`features/canvas/nodes/TextOverlay.tsx`): у Konva нет редактируемого текста,
  поэтому `<textarea>` абсолютно позиционируется поверх холста, координаты
  считаются из мировых через трансформ вьюпорта, по `blur` значение уезжает в узел.
- **Не подключать tldraw, excalidraw и подобные готовые доски** — это чужой продукт целиком.
- Состояние — Zustand + Immer, не Redux и не контекст.
- Хранение — IndexedDB через `idb`. localStorage не потянет изображения-блобы.
- Библиотеки только из [docs/TOOLING.md](docs/TOOLING.md), раздел 1. Не заменять
  на привычные аналоги, не добавлять сверх списка.

## Устройство холста

`CanvasStage` — корень: `ResizeObserver` пишет `canvasSize` в стор, `useCanvasGestures`
(@use-gesture/react) переводит колесо/трекпад/пинч в `panBy` и `zoomAt`.

**Три слоя Konva, порядок важен:**

1. `GridLayer` — фон, не масштабируется вьюпортом;
2. слой содержимого — `NodesLayer` и призрак создаваемого узла;
3. **слой выделения** — рамка, трансформер, подсветка якорей коннектора.

Выделение вынесено в отдельный слой намеренно: в общем слое каждый клик
и каждое движение рамки перерисовывали бы всю доску.

Поверх канваса — `EditingOverlay`: обычный `<textarea>` для ввода текста.

Координаты живут в двух пространствах — экранном и мировом; перевод между ними
в `engine/viewport.ts`, это единственное место, где он должен быть.
`engine/contract.ts` и `nodes/contract.ts` держат типы-контракты слоя.

`NodesLayer` разводит узлы по типам в таблицу рендереров. Новый тип узла добавляется
процедурой из скилла `canvas-node-type` — шесть шагов, пропуск любого стоит дороже,
чем кажется.

Сетка рисуется слоем с `listening={false}`: Konva не строит для него hit-канвас,
клики проваливаются сквозь неё к содержимому.

Узлы слушают мышь **только под инструментом «Выбор»** (`NodesLayer`). Иначе
протяжка инструментом создания, начатая на фигуре, тянет саму фигуру:
Konva видит нажатие на `draggable`-узле раньше, чем событие доходит
до инструмента.

Соединители устроены иначе всех: у `ConnectorNode` нет рамки, он единственный
не наследует `BaseNode`. Маршрут считает `canvas/connectors/routing.ts` —
единственная точка правды, оттуда же берут точки подпись и наконечники.

## Производительность — не оптимизируй в обратную сторону

Цель — 1000 объектов при панорамировании и зуме не ниже 50 fps (NFR-01).
В зависимостях `useMemo`/`useEffect` на горячих путях намеренно стоят **примитивы**,
а не объекты `viewport`/`size`: они пересоздаются на каждый рендер родителя и
обнулили бы мемоизацию. Там, где Biome с этим спорит, стоит `biome-ignore` с
причиной — не «чини» их автофиксом.

**Замерено, а не предположено** (`e2e/perf.spec.ts`, 27.08): на тысяче узлов
55 fps — требование выполняется, но 95-й процентиль разрыва между кадрами
33 мс против 17 на пустой доске, то есть теряется примерно каждый десятый кадр.
Коннекторы **не дороже** фигур: 300 линий вместо 300 фигур не стоили ничего
измеримого, хотя маршрут считается на кадре. Значит, выигрыш даст не оптимизация
маршрутов, а отсечение по видимой области — его нет. Пороги в тесте
сравниваются с базовой линией, снятой в том же прогоне, а не с константой:
иначе тест мерил бы машину, а не доску.

## Хуки и журнал сессий

`.claude/hooks/` подключены в `.claude/settings.json`:

- `log-prompt.sh` (`UserPromptSubmit`) — пишет каждый промпт в `sessions/$DEV_NAME/ГГГГ-ММ-ДД.md`.
- `log-response.sh` (`Stop`) — дописывает туда же ответ агента. Текст берёт
  из транскрипта по `transcript_path`: в полезной нагрузке хука самого ответа
  нет. Стоит **перед** `gate-stop.sh` — тот умеет вернуть код 2 и не дать
  сессии закончиться, и тогда ответ остался бы незаписанным.
- `guard-secrets.sh` / `guard-bash.sh` (`PreToolUse`) — блокируют запись в секреты,
  снос корня, форс-пуш, переключение на `main`.
- `format-file.sh` (`PostToolUse` на `Write|Edit`) — прогоняет `biome check --write`
  по изменённому файлу.
- `format-changed.sh` (`PostToolUse` на `Bash`) — то же, но список файлов берёт
  у git. Нужен потому, что запись через heredoc, `sed` или скрипт проходит мимо
  `Write|Edit`, и форматирование копилось молча до самого `Stop`.
- `gate-stop.sh` (`Stop`) — typecheck и линт; при провале не даёт закончить сессию.
  Второй подряд отказ пропускает, чтобы не зациклиться.

`gate-stop.sh` означает, что **сессия не закончится с красным линтом или типами.**
Не обходи его правкой `biome.json` — чини код.

Проверка самих хуков — `bash .claude/hooks/guard-bash.test.sh`: восемнадцать
случаев «команда → ожидание», включая оба известных обхода и шесть ложных
срабатываний. Правишь регэксп в `guard-bash.sh` — прогоняй её, иначе починка
тихо сломает то, что раньше ловилось.

## Git-хуки

`lefthook.yml`, ставятся сами через `npm run prepare` после `npm install`.

- `commit-msg` → `scripts/check-contract-commit.sh` — не даёт закоммитить правку
  общего шва (`shared/types/document.ts`, `shared/store/`) без префикса
  `contract:`. Снимается `CONTRACT_OK=1 git commit`, если контракт не меняется.
- `pre-commit` — типы и `biome` по изменённым файлам. Тесты и e2e здесь
  намеренно не стоят: полный прогон на каждый коммит превращает хук в тот,
  который обходят через `--no-verify`. Они — в `workflows/pre-merge.md`.

## MCP

`.mcp.json` в корне, подключается всем, кто открывает проект.

- **context7** — свежая документация библиотек в контекст. Konva агенты помнят
  плохо и уверенно выдумывают API, а `resolve-library-id` для Konva отдаёт
  `/konvajs/site` с 2481 сниппетом. Ключ не нужен, запускается через `npx`.
  Инструменты: `resolve-library-id` (принимает **оба** аргумента — `libraryName`
  и `query`) и `query-docs`.
