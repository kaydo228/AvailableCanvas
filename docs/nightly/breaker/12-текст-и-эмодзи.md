# 12.1 — стикер со всякой строкой

| содержимое | кадр |
|---|---|
| 100 000 символов | **333 мс** |
| 5 000 символов без единого пробела | 25 мс |
| 200 повторов «семья + флаг + рука с модификатором тона» (ZWJ-последовательности) | 57 мс |
| 5 000 переводов строки подряд | 21 мс |
| 500 повторов буквы с восемью комбинирующими диакритиками | 33 мс |
| строка с `U+202E` (разворот направления) и `U+202D` | 32 мс |
| строка, оканчивающаяся половинкой суррогатной пары (`\uD83D`) | 32 мс |

Единственное, что стоит записать: **100 тысяч символов в одном стикере —
333 мс на кадр**, то есть треть секунды видимого замирания при вставке.
Это не поломка, но ограничения на длину текста нигде нет, а буфер обмена
такие строки даёт легко (вставка кода, лога, статьи).

Половинка суррогатной пары и `U+202E` не роняют ни Konva, ни сериализацию
в IndexedDB — я ожидал проблем именно здесь.

# 12.2 — длинные подписи

Подпись коннектора в 24 000 символов на кривой маршрутизации — 24 мс.
Подпись фигуры в 20 000 символов — без ошибок. **Не сломалось.**

# 12.3 — узел исчезает во время ввода в оверлей

Открыл `<textarea>` над текстовым узлом, набрал строку с переводами
строк, эмодзи-семьёй и табуляцией, и **не завершая ввод** удалил узел
из документа. Затем щёлкнул мимо (`blur`).

```
узлы после: []
editingNodeId: null
оверлей остался: 0
```

`removeNodes` гасит `editingNodeId`, если удаляется редактируемый узел,
и оверлей снимается сам. Ни повисшей `<textarea>`, ни попытки записать
текст в несуществующий узел. **Не сломалось** — это тот же класс гонки,
что 08.2, но здесь он закрыт.

# 12.4 — `autoWidth` и строка в 50 000 символов

Узел с `autoWidth: true` и очень длинным текстом остался `100×40` —
ширина не подстроилась. Ошибок нет, но подгонка ширины, судя по всему,
происходит только на пути ввода через оверлей, а не при появлении текста
в модели другим способом (импорт, дублирование, вставка через стор).
Мелочь, записываю для полноты.
