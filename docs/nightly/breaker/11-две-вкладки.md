---
title: "Итерация 11 — две вкладки на одной доске"
---

Проба: [`probes/11-tabs.spec.ts`](probes/11-tabs.spec.ts).

```bash
npx playwright test --config=docs/nightly/breaker/probes/playwright.config.ts 11-tabs
```

**Сломать не удалось.** Записываю подробно, потому что это единственное
место, где я заранее рассчитывал на потерю данных, и её нет.

# 11.1 — обе вкладки правят одновременно

Вкладка A добавляет узел, вкладка B добавляет свой. Через 2.5 с:

- в базе оказался узел вкладки A (`["fromA"]`) — первая успевшая запись;
- вкладка B получила **вечный тост** «Доска изменена в другой вкладке.
  Обновите страницу — иначе ваши правки не сохранятся»;
- индикатор в шапке B стоит на «Изменена в другой вкладке» и не гаснет;
- вкладка A ничего не заметила и продолжает работать — правильно, её данные
  в базе;
- ошибок в консоли нет ни в одной вкладке.

Дальнейшие правки в B принимаются на экране, но в базу не идут и **нового
тоста не порождают** — по одному объявлению на состояние, чтобы не спамить.
Индикатор остаётся тревожным всё это время, так что человек не остаётся
без сигнала. Единственный выход для B — «Экспорт», как и написано в тосте;
это осознанное решение (слияния досок нет), а не пропуск.

# 11.2 — одна вкладка удаляет проект, вторая продолжает рисовать

Вкладка B получает по `BroadcastChannel`:

```
Проект удалён в другой вкладке
Сохранять больше некуда. Выгрузите доску через «Экспорт», если она нужна.
```

Дальнейшее рисование не роняет ничего: попыток записи в несуществующий
проект нет, исключений нет, вкладку не выкидывает с маршрута (и правильно —
выкинуть значило бы уничтожить последнюю копию доски).

# Что проверил и что не сломалось

- одновременная запись двух вкладок → конфликт виден, данные первой целы;
- удаление проекта под открытой вкладкой → предупреждение, без падения;
- правки после конфликта → не пишутся, индикатор остаётся тревожным;
- перезагрузка конфликтной вкладки → читается версия из базы.
