# 09.1 — собрать группу из 1000 узлов и продублировать её

| шаг | время |
|---|---|
| добавить 1000 узлов | 138 мс |
| `group(1000 id)` | 15 мс |
| `duplicateNodes([группа])` | **8 мс**, создано 1001 узлов |
| `zoomToFit` на 2002 узлах | 358 мс |

Документ после: 2002 узла в `nodes`, 2002 в `order` — сходится.
Нарушений инвариантов нет, ошибок в консоли нет, интерфейс не подвисает.

Ожидал здесь квадратичного обхода (`duplicateNode` для группы ходит
по `clones` на каждого ребёнка), но карта клонов — `Map`, и обход линейный.
**Не сломалось.**

# 09.2 — поворот и растяжение группы из 1000 узлов

| операция | время |
|---|---|
| `rotate 30` | 13 мс |
| `rotate` обратно в 0 | 5 мс |
| `resize` до 500×300 | 8 мс |
| `moveNodes` | 3 мс |

Поворот на тысяче узлов обратим так же точно, как на двух. Рамка группы
после растяжения — ровно `500 × 300.00000000000006`, то есть запрошенная.
**Не сломалось.**

Единственное, что стоит записать: `resyncGroups` вызывается на каждый кадр
перетаскивания и каждый раз пересчитывает `groupBounds` по **всем** потомкам.
На тысяче узлов это 3–13 мс за вызов, то есть при перетаскивании такой группы
мышью кадровый бюджет 16 мс съедается почти целиком одним пересчётом рамки.
Замера fps на перетаскивании группы в `e2e/perf.spec.ts` нет — там меряется
панорамирование и зум. Это не находка, а незакрытая дыра в замере.
