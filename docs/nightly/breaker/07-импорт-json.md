---
title: "Итерация 07 — импорт JSON: чужие, битые и вывернутые файлы"
---

Импорт делается настоящей кнопкой «Импорт JSON» на экране списка,
файл подсовывается через `setInputFiles` — то есть путь ровно тот же,
что у человека.

Проба: [`probes/07-import.spec.ts`](probes/07-import.spec.ts).

```bash
npx playwright test --config=docs/nightly/breaker/probes/playwright.config.ts 07-import
```

# 07.1 — мусорные файлы: отбиты все, тексты человеческие

| файл | ответ |
|---|---|
| чужая схема (`{nodes:[], version:'excalidraw'}`) | «Это не файл доски Prostor: в нём нет отметки формата «prostor-board»…» |
| обрезанный на 60 % | «Файл не читается как JSON — похоже, он повреждён или скачался не полностью…» |
| пустой файл | то же |
| `[1,2,3]` | «В файле не объект. Это не доска Prostor.» |
| `version: 2` | «Файл сделан более новой версией Prostor: версия файла 2, а здесь понимают 1.» |

Ни одного перехода на маршрут доски, ни одной ошибки в консоли,
ни одного пустого проекта-огрызка в списке. **Не сломалось.**

# 07.2 — дубли в `order` и висячий id: чинятся и о починке говорят

`order: ['a','a','a','ghost','b']` → `['a','b']`, тост-предупреждение
перечисляет что именно поправили. Валидатор после импорта чист.
**Не сломалось.**

# 07.3 — односторонняя связь с группой (НАХОДКА)

**Что сделал.** Файл, где `b.groupId = 'g'`, но `g.children = ['a']` —
ребёнок знает про группу, группа про него не знает.

**Что ожидалось.** Либо починка (одну из двух сторон привести к другой),
либо хотя бы предупреждение.

**Что произошло.** Файл открылся **без единой починки** — тост
«Доска «Импорт» открыта», валидатор молчит. И дальше группа ведёт себя
так, будто `b` в ней нет, а `b` — будто он в ней есть:

```
moveNodes(['g'], 100, 0)  →  a.x = 100,  b.x = 400 (не сдвинулся)
рамка g осталась 100×100, хотя b «внутри» неё
```

Что это значит для человека: клик по `b` даёт `topmostGroup(b) = 'g'`,
выделение раскрывается в `withGroupDescendants(['g'])` = `[g, a]` —
**узел `b` не попадает даже в собственное выделение**. Дальше перетаскивание
двигает `a`, а не `b`; `Delete` удаляет `g` и `a`, а `b` остаётся сиротой
с `groupId`, указывающим на исчезнувшую группу.

`repair.ts` чистит `children` от несуществующих детей (одна сторона),
но обратную ссылку `groupId` не проверяет вовсе. Валидатор про группы
не знает ничего: среди пяти инвариантов правила про двустороннюю связь нет,
хотя `operations.ts` прямо называет её «двусторонней связью, избыточной
намеренно».

**Воспроизводится стабильно.** Достижимо только через файл — интерфейс
такую связь не собирает.

# 07.4 — концы линий: чинятся правильно

| в файле | стало |
|---|---|
| `from: {nodeId:'a', point:{5,5}}` (оба) | `{nodeId:'a', anchor:'auto'}` — точка отброшена |
| `to: {}` (ни одного) | `{point:{60,40}}` — центр противоположной фигуры |
| `from: {nodeId:'нетТакого'}` | `{point:{1,1}}` — тянется к другому концу |

Всё соответствует инварианту 3 и обещаниям в комментариях. Тост честно
перечисляет починки. **Не сломалось.**

# 07.5 — коннектор в составе группы: инвариант 2 проверяется только с одной стороны (НАХОДКА)

**Что сделал.** Файл, где `g.children = ['a','c1','g']` — то есть в детях
группы лежит коннектор `c1` и сама группа `g`. У `c1` в файле был ещё
и `groupId: 'g'`.

**Что произошло.**

- `groupId` у коннектора починка **сняла** (инвариант 2, одна сторона);
- запись `c1` в `g.children` **осталась** — тоста об этом нет;
- `validateDocument` документ считает **чистым**;
- самоссылка `g` в собственных детях тоже осталась, обходы её переживают.

Итог: линия наполовину в группе. `moveNodes` её пропускает (у коннектора
нет рамки), а `removeNodes(['g'])` уносит вместе с группой — проверил,
после удаления группы в документе не осталось **ничего**, включая `c1`.

То есть инвариант 2 записан как «`ConnectorNode` не участвует в `groupId`»
и ровно так и проверяется — по полю `groupId`. Вторая сторона той же связи,
`GroupNode.children`, не проверяется ни валидатором, ни починкой, и через неё
коннектор в группу заводится свободно.
