# 05.1 — `resizeNode` держит удар

| подано | получено |
|---|---|
| `0 × 0` | `8 × 8` |
| `−300 × −200` | `8 × 8` |
| `0.0001 × 1e9` | `8 × 1e9` |
| `x=NaN, height=NaN` | откат к текущим значениям |
| `width=Infinity` | откат к текущему |
| `1e308` во всех полях | принято как есть |

`sanitizeBox` + `clampSize` работают как обещано. Единственное, что проходит
насквозь, — `1e308`: узел размером в число, близкое к пределу double. Konva
это переживает, экспорт — вопрос, но отдельной находкой считать не стал.

# 05.2 — `updateNode` не проверяет геометрию вовсе (НАХОДКА)

Тот же мусор, поданный через `updateNode`, а не `resizeNode`, уезжает
в модель без единой проверки:

| патч | стало |
|---|---|
| `{width: -500}` | **width = −500** |
| `{width: 0}` | **width = 0** |
| `{height: NaN}` | **height = NaN** |
| `{width: Infinity}` | **width = Infinity** |
| `{opacity: 99}` | 1 (зажато) |
| `{opacity: NaN}` | 1 (зажато) |
| `{opacity: -3}` | 0 (зажато) |

`sanitize` в сторе приводит ровно два поля — `opacity` и `rotation`, —
а `width`/`height`/`x`/`y` пропускает. Комментарий над действием объясняет,
почему прозрачность зажимается «здесь, а не у вызывающего» («проверять
в каждом месте — верный способ однажды забыть»); ровно это и произошло
с размерами.

Через нынешний интерфейс так сделать нельзя: `NumberField` в панели свойств
отбрасывает `NaN` и зажимает по `min`. Но `updateNode` — **действие общего
контракта**, зона B зовёт его из пяти секций инспектора и из оверлея текста,
и ничто не мешает шестой передать вычисленную ширину, получившуюся `NaN`
из деления на ноль. Последствия — итерация 06.

# 05.3 — `setViewport` пропускает зум мимо инварианта 5 (НАХОДКА, нарушение инварианта)

```
setViewport({zoom: 99})       → 99
setViewport({zoom: -1})       → -1
setViewport({zoom: 0})        → 0
setViewport({zoom: NaN})      → NaN
setViewport({zoom: Infinity}) → Infinity
setViewport({zoom: 4.0001})   → 4.0001
```

Валидатор это видит и говорит прямо:

```json
[{"rule":5,"message":"зум 4.0001 вне диапазона [0.1, 4]"}]
```

Это **единственное за прогон прямое нарушение одного из пяти инвариантов**,
достижимое через публичное действие стора.

Для сравнения, соседи защищены честно: `zoomAt` с множителем 100 трижды
подряд упирается ровно в 4, с множителем 0.0001 — ровно в 0.1, `zoomAt`
с `NaN` ничего не меняет. Границы держит `clampZoom` внутри `zoomAt`,
а `setViewport` его не зовёт — пишет переданное значение как есть.

Из интерфейса это сейчас недостижимо: единственный вызывающий —
`CanvasStage`, и он получает вьюпорт из `useCanvasGestures`, где всё уже
прошло через `zoomAt`/`panBy`. То есть дыра **латентная**: она в контракте,
не в экране. Но контракт для того и написан, чтобы им пользовались, —
а `panBy(NaN, NaN)` рядом даёт `viewport = {x: NaN, y: NaN}` и гасит
холст целиком.

Смягчает: `persistence/repair.ts` чинит вьюпорт при чтении из базы,
поэтому «навсегда» такой документ не ломается — только до перезагрузки.

# 05.4 — `zoomToFit` на пустой доске и на коннекторе от −1e9 до 1e9

Пустая доска → `{x:0, y:0, zoom:1}`, честный запасной вариант.
Коннектор длиной два миллиарда единиц → `{x:0, y:0, zoom:1}`, без `NaN`
и без ухода в бесконечность. **Не сломалось.**
