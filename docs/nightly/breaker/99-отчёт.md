# Как читать

Пятнадцать итераций, по файлу на каждую: `01-…` … `15-…`. Здесь только
итог. Воспроизведение каждой находки — проба в
[`probes/`](probes/), запускается своим раннером и **не трогает `e2e/`**:

```bash
npx playwright test --config=docs/nightly/breaker/probes/playwright.config.ts 01-groups 02-stale 03-dup 04-rot 05-size
npx playwright test --config=docs/nightly/breaker/probes/playwright.config.ts 06-nan 07-import 08-races
npx playwright test --config=docs/nightly/breaker/probes/playwright.config.ts 09-thou 10-resize 11-tabs
npx playwright test --config=docs/nightly/breaker/probes/playwright.config.ts 12-text 13-lazy 14-export 15-verify
```

Партиями, а не одной командой: полный прогон всех пятнадцати файлов в одном
процессе убивается по памяти (тысяча узлов, стикер на 100 000 символов
и PNG 6168×4128 в одном контексте). Партиями всё зелёное.

**Все 45 сценариев прогнаны повторно и стабильны.** Единственный красный —
`02.1`: он написан как обвинение и падает намеренно, показывая устаревшую
рамку группы (1120 вместо 320).

Ничего не чинил: правил только эту папку.

# Находки по опасности

## 1. Коннектор создаётся со ссылкой на уже удалённый узел

**Итерация 08.2.** Инструментом «Линия» тянем от фигуры `a` к фигуре `b`;
пока кнопка не отпущена, `a` исчезает (второй пользователь, автосинхронизация,
собственный `Delete`). На `mouseup` создаётся коннектор с
`from: {nodeId: 'a'}` — узла с таким id в документе нет.

Инструмент запоминает `Endpoint` на `mousedown` и отдаёт его в `connect()`
как есть; существование узла не проверяет никто. Инвариант 4 здесь не
работает — линия создана **после** удаления.

Линию не видно и не выделить, но она уезжает в IndexedDB. При следующем
открытии доски приложение **само сообщает о повреждении**:

```
Доска была повреждена, пришлось поправить
линия 27ee026d…, конец «from»: узел a не существует — конец отвязан
```

*Опасность:* порча документа обычными действиями интерфейса, тихая,
без единой ошибки в консоли. Лечится починкой на входе — то есть
только до перезагрузки доска остаётся битой.
*Воспроизводится стабильно* (два независимых прогона).

## 2. Сжатие группы и возврат необратимо разрушают её содержимое

**Итерация 10.1.** Группа из трёх фигур 120×80. Тянем угол рамки внутрь
до минимума и возвращаем обратно — одним жестом мыши, каждый кадр которого
зовёт `resizeNode`.

```
исходно         : a 120×80    b 120×80    c 120×80
сжали до 10×10  : a 8×8       b 8×8       c 8×8       ← clampSize
вернули 1120×480: a 529×235   b 529×235   c 529×235
```

Рамка группы вернулась точно, содержимое — нет: три карточки стали тремя
перекрывающимися плитами. Пол `MIN_NODE_SIDE = 8` применяется к каждому
ребёнку отдельно и уничтожает информацию о пропорции; обратный масштаб
считается от уже искажённых границ.

Контрольный опыт (10.2): тот же круг без упора в минимум — растянуть
в 1000 раз и вернуть — восстанавливает всё **точно**. Значит виноват зажим,
а не математика.

*Опасность:* потеря данных обычным жестом, без предупреждения. Спасает
только `Cmd+Z`, если человек заметит.
*Воспроизводится стабильно.*

## 3. `Cmd+D` по группе теряет все линии внутри группы

**Итерации 03.1 и 15.1** (второе — настоящей клавиатурой). Схема из двух
фигур со стрелкой, собранная в группу; `Cmd+D` даёт копию из двух фигур
**без стрелки**.

Коннектор по инварианту 2 в группу не входит, поэтому его нет ни в
`withGroupDescendants(группа)`, ни в выделении, которое ставит `group()`.
Перевязка ссылок при этом работает: если выделить группу И коннектор явно,
копия линии смотрит на копии фигур (03.2).

*Опасность:* самая частая операция над диаграммой даёт неверный результат.
Оригинал цел — данные не теряются, но копия бесполезна.
*Воспроизводится стабильно.*

## 4. Рамка группы не пересчитывается после удаления — и группа переживает своё содержимое

**Итерации 01.1, 02.1, 02.3, 06.2, 14.1.** Один корень, пять следствий.

`removeNodes` заканчивается вызовом `resyncGroups(document, expanded)`, где
`expanded` — **только что удалённые** id. `resyncGroups` берёт узел по id,
чтобы узнать его `groupId`; узла уже нет, очередь остаётся пустой, цикл
не выполняется. Пересчёт после удаления не делает ничего
(`shared/store/board.ts:390`, обход — `:183`).

Следствия:

- удалили ребёнка — рамка группы осталась прежней (0→1120 вместо 0→320);
- удалили **всех** детей — группа осталась в `nodes` и `order` с пустым
  `children` и старой рамкой: невидимый, неудаляемый мышью призрак;
- `zoomToFit` вписывает вид в рамку призрака: на доске одна фигура 100×100,
  а зум встал в 0.178 «под 5120×3080»;
- экспорт PNG выдаёт **6168×4128 пустоты** (656 КБ), и добавленная рядом
  настоящая фигура занимает в ней 0.06 % площади;
- починка документа на входе рамки групп тоже не пересчитывает: после
  `repair.ts` группа остаётся расходящейся с содержимым, и это состояние
  уже лежит на диске.

*Опасность:* устаревшая геометрия живёт в IndexedDB и переживает
перезагрузку; чинится только сдвигом какого-нибудь ребёнка вручную.
Ни один из пяти инвариантов при этом не нарушен — валидатор молчит.
*Воспроизводится стабильно.*

## 5. `setViewport` пропускает зум мимо инварианта 5

**Итерация 05.3.** Единственное прямое нарушение одного из пяти инвариантов
за весь прогон:

```
setViewport({zoom: 99})  → 99      setViewport({zoom: NaN})      → NaN
setViewport({zoom: -1})  → -1      setViewport({zoom: Infinity}) → Infinity
setViewport({zoom: 0})   → 0       setViewport({zoom: 4.0001})   → 4.0001
```

`validateDocument` подтверждает: `{"rule":5,"message":"зум 4.0001 вне
диапазона [0.1, 4]"}`. Рядом `panBy(NaN, NaN)` даёт `viewport {x: NaN, y: NaN}`
и гасит холст целиком.

Соседние действия защищены честно: `zoomAt ×100` трижды упирается ровно
в 4, `×0.0001` — ровно в 0.1, `zoomAt(NaN)` ничего не меняет. Границы держит
`clampZoom` **внутри `zoomAt`**, а `setViewport` его не зовёт.

*Опасность:* дыра в контракте, а не на экране — единственный вызывающий
(`CanvasStage`) получает уже зажатый вьюпорт. Но `setViewport` — публичное
действие общего шва, и `repair.ts` чинит зум только при чтении из базы.
*Воспроизводится стабильно.*

## 6. `updateNode` не проверяет геометрию — узел исчезает молча

**Итерации 05.2 и 06.1.**

```
updateNode('a', {width: -500})     → width = -500
updateNode('a', {width: 0})        → width = 0
updateNode('a', {height: NaN})     → height = NaN
updateNode('a', {width: Infinity}) → width = Infinity
```

`sanitize` в сторе приводит ровно два поля — `opacity` и `rotation`.
Комментарий над действием объясняет, почему прозрачность зажимается именно
здесь («проверять в каждом месте — верный способ однажды забыть»); ровно это
и произошло с размерами.

Что видно человеку: после `width: NaN` число закрашенных пикселей на слое
содержимого падает ровно вдвое — узел перестаёт рисоваться. **Ни одной
ошибки в консоли**, узел остаётся в `nodes` и `order`, мышью его больше
не поймать, валидатор молчит.

*Опасность:* из нынешнего интерфейса недостижимо (`NumberField` отбрасывает
`NaN` и зажимает по `min`), но `updateNode` зовут пять секций инспектора
и оверлей текста — вычисленная ширина с делением на ноль попадёт туда без
сопротивления.
*Воспроизводится стабильно.*

## 7. Односторонняя связь с группой не чинится и не проверяется

**Итерации 07.3 и 15.2.** Файл, где `b.groupId = 'g'`, а `g.children = ['a']`,
импортируется **без единой починки** и без предупреждения. Дальше:

```
selectionForClick(doc, 'b')  →  ["g","a"]     ← самого b в выделении нет
moveNodes(['g'], 100, 0)     →  a.x = 100, b.x не изменился
```

Щёлкнув по узлу, человек выделяет всё, кроме него. Группа не двигает его
за собой, но `Delete` по группе унесёт `g` и `a`, оставив `b` сиротой
со ссылкой на исчезнувшую группу.

`repair.ts` чистит `children` от несуществующих детей — одну сторону связи.
Обратную (`groupId`) не проверяет никто, и среди пяти инвариантов правила
про двустороннюю связь нет, хотя `operations.ts` прямо называет её
«двусторонней связью, избыточной намеренно».

*Опасность:* достижимо только через файл. Документ формально валиден.
*Воспроизводится стабильно.*

## 8. Инвариант 2 проверяется только с одной стороны

**Итерация 07.5.** Инвариант записан как «`ConnectorNode` не участвует
в `groupId`» и ровно так и проверяется — по полю `groupId`. Вторая сторона
той же связи, `GroupNode.children`, не проверяется ни валидатором,
ни починкой.

Файл с `g.children = ['a','c1','g']` (внутри — коннектор и сама группа)
открывается чистым: `groupId` у коннектора починка сняла, запись в
`children` оставила. Линия оказывается наполовину в группе: `moveNodes`
её пропускает, а `removeNodes(['g'])` уносит вместе с группой — проверил,
после удаления группы в документе не осталось ничего.

*Воспроизводится стабильно.*

## 9. Минимальный размер узла: 1 в панели против 8 в движке

**Итерация 06.3.** `MIN_NODE_SIDE = 8` («меньше этого узел невозможно поймать
мышью»), а поля ширины и высоты в панели свойств стоят с `min={1}`.
Узел 1×1 создаётся штатной панелью и после этого действительно не ловится
мышью. Две границы разъехались.

## 10. Растяжение группы с повёрнутым содержимым промахивается мимо рамки

**Итерация 04.5.** Группа из повёрнутой на 45° фигуры и обычной. Просили
рамку `{0, 0, 100×50}` — получили `x = −3.84, width = 103.84`. Около 4 %,
не накапливается. Косметика, но при сильном сжатии станет заметной.

## 11. Мелочи, записанные для полноты

- **Коннектор нулевой длины** (03.3): петля `a→a`, у которой удалили `a`,

- **`/p/несуществующий` молча редиректит на список** (13.4), тогда как

# Что проверено и НЕ сломалось

Перечисляю честно: половина прогона ушла на сценарии, которые доска
выдержала.

**Поворот** (итерация 04) — единственная из четырёх новых фич, выдержавшая
всё: `rotate(90)` и обратно возвращает координаты **точно**; то же на 45°;
сто поворотов по градусу дают тот же результат, что один на 100°, без
дрейфа; `720 → 0`, `−0 → +0` (не минус-ноль), `NaN → 0`, `Infinity → 0`,
`1e9 → 280`, `updateNode({rotation: 370}) → 10`.

**Циклы в группах** — `g1 ⊂ g2 ⊂ g1` через `loadDocument`, затем `move`,
`rotate`, `resize`, `duplicate` по нему: ни зависания, ни переполнения
стека. Обходы защищены множеством посещённых, и защита работает.

**Роспуск вложенной группы** (01.3) — состав переходит внешней группе
верно, без дублей и висячих ссылок.

**`resizeNode`** (05.1) — `0×0 → 8×8`, `−300×−200 → 8×8`, `NaN` откатывается
к текущему значению, `Infinity` тоже.

**`zoomAt` / `zoomToFit`** (05.3, 05.4) — упираются ровно в границы;
пустая доска и коннектор длиной два миллиарда дают `zoom: 1`, без `NaN`.

**Импорт мусора** (07.1) — чужая схема, файл, обрезанный на 60 %, пустой
файл, `[1,2,3]`, `version: 2`: все отбиты с человеческими текстами, без
перехода на маршрут доски и без проектов-огрызков.

**Починка `order` и концов линий** (07.2, 07.4) — дубли и висячие id
убираются, конец с `nodeId` и `point` разом сводится к `nodeId`, пустой
конец — к точке, ссылка на несуществующий узел отвязывается. Обо всём
докладывает тост.

**Гонки удаления** (08.1, 08.3, 08.4, 08.5) — удаление узла посреди его
перетаскивания, удаление целевого узла посреди рисования линии, удаление
группы посреди перетаскивания участника, `Delete` с клавиатуры прямо
в жесте: всё чисто. Сломался только один из пяти вариантов — 08.2.

**Тысяча узлов в одной группе** (09) — `group` 15 мс, `Cmd+D` 8 мс на 1001
узел, `rotate` 13 мс, `resize` 8 мс, `move` 3 мс, `zoomToFit` 358 мс.
Инварианты целы, консоль чиста.

**Две вкладки** (11) — одновременная правка даёт конфликт, данные первой
вкладки целы, вторая получает вечный тост и тревожный индикатор; удаление
проекта под открытой вкладкой не роняет её и не выкидывает с маршрута.

**Текст** (12) — 100k символов, 5000 символов без пробелов, ZWJ-эмодзи
с модификаторами тона, 5000 переводов строки подряд, восемь комбинирующих
диакритиков, `U+202E`, половинка суррогатной пары: ни одной ошибки.
Узел, удалённый прямо во время ввода в оверлей, гасит оверлей корректно.

**Ленивый маршрут** (13) — с искусственной задержкой куска `CanvasScreen`
в 3 секунды: клавиши `Delete`/`Cmd+A`/`Cmd+D`/`Cmd+G`/`Cmd+Z` в окно
ожидания ничего не делают; уход назад до монтирования не затирает базу;
восемь метаний по истории подряд не оставляют следов.

**Экспорт** (14) — пустая доска отбита текстом, узел 10⁶×10⁶ отбит
с объяснением про предел 16384, круг «экспорт JSON → импорт» на доске
с группой, повёрнутым узлом и коннектором замыкается без потерь.

# Три вывода

1. **Всё, что проверяется явно, — держится.** Пять инвариантов, `clampZoom`,
   `sanitizeBox`, схема импорта, `repair.ts`, обходы с защитой от циклов:
   я бил во всё это и пробил ровно один раз (`setViewport`).
2. **Ломается то, что производно и держится «конструкцией кода».** Рамка
   группы, двусторонняя связь `groupId ↔ children`, состав дублируемого
   набора — ни одно из этих правил не записано ни инвариантом, ни проверкой,
   и все три расходятся с моделью. Четыре из одиннадцати находок — это они.
3. **Из четырёх фич, влитых 27 августа, поворот безупречен, а группы,
   дублирование и изменение размера дали по находке каждая** — и все три
   в местах, где операция взаимодействует с производной геометрией группы.
   Слияние трёх параллельных worktree, о котором предупреждало задание,
   стык в `SelectionTransformer.tsx` не сломало: ломается общая модель
   групп, а не место склейки.
