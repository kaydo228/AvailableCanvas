| Изменение размера, `store.resizeNode` | `canvas/selection/resize.ts` | растяжение группы масштабирует содержимое |

Три из них делались **параллельно, в разных worktree**, и сводились слиянием
с ручным разбором конфликта в `SelectionTransformer.tsx`. Место, где слияние
могло оставить полуработающий стык, — самое перспективное для поиска.

Ещё три правки от 28 августа, тоже никем не проверявшиеся:

- **маршрут холста грузится лениво** (`React.lazy` в `app/router.tsx`) —
  интересен момент между сменой адреса и монтированием: что будет, если
  в это окно успеть нажать клавиши, уйти назад, открыть вторую вкладку;
- **шрифты локальные** (`public/fonts`) — не про поломку, но проверить,
  что подписи на холсте не поехали;
- **экспорт и импорт JSON** живут теперь в разных модулях

# Чем ломать: рычаги, которые есть

**Стор открыт наружу.** `main.tsx` кладёт его в `window.__board`, поэтому
из консоли браузера или из `page.evaluate` доступно всё:

```js
window.__board.getState().loadDocument({ ...doc, nodes, order }); // подсунуть документ
window.__board.getState().group(['a', 'b']);                      // вызвать действие мимо интерфейса
window.__board.getState().document;                                // посмотреть, что вышло
```

Это главный вход: через него кладутся документы, которые интерфейс собрать
не даст, — с дублями в `order`, с висячими ссылками, с узлом внутри самого себя.

**Инварианты записаны и проверяемы.** Пять штук в `CLAUDE.md`, раздел
«Инварианты модели». Валидатор — `shared/model/invariants.ts`,
функция `validateDocument`: ей можно скормить свой документ и спросить,
что нарушено. **Нарушение инварианта — самая ценная находка**, потому что
такой документ уезжает в IndexedDB и ломает доску навсегда, а не до
перезагрузки.

**Приложение поднимается** `npm run dev`, сценарии удобно гонять Playwright'ом
(`npx playwright test --project=e2e`). Импорт битого файла проверяется через
кнопку «Импорт JSON» на экране списка.

**Что уже прикрыто починкой на входе:** `features/persistence/repair.ts`
чинит документ и при импорте файла, и при чтении из базы. Поэтому «подсунул
битый JSON — доска не открылась» скорее всего не воспроизведётся: интереснее
искать, что `repair` **не** чинит и что можно испортить уже после загрузки.

# Правила прогона

1. **Ничего не чинить.** Правится только эта папка. Находка ценна описанием
   и воспроизведением, а не патчем: чинить будет автор, зная контекст.
2. **Минимум десять итераций**, каждая — своим файлом. Даже неудачная:
   «пробовал X, не сломалось» — это тоже результат и он экономит время
   следующему.
3. **Воспроизводимость важнее эффектности.** У каждой находки: что сделал,
   что ожидалось, что произошло, воспроизводится ли стабильно.
4. **Пустой отчёт не принимается.** Если сломать не удалось — перечислить,
   что именно проверено.
5. Итоговый список — **по опасности**: падение приложения → нарушение
   инварианта (уезжает в базу) → потеря данных → чушь на экране → косметика.
