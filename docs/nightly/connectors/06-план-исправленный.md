# Что проверка плана изменила

Четыре находки приняты, все проверены мной лично, а не на слово.

## 1. `useShallow` на объекте `Route` — принято, план был неверен

Проверил `node_modules/zustand/vanilla/shallow.js`: сравнение идёт **на один
уровень** через `Object.is`, а массивы и итерируемые — поэлементно.
Объект `Route` с полями `points` (новый массив) и `startTangent` (новый
объект) даст `false` при каждом сравнении. Это не «мемоизация не сработала»,
а новая ссылка из `getSnapshot` на каждый вызов, то есть цикл перерендеров.

**Решение:** селектор возвращает **плоский `number[]`** — для него
`compareIterables` работает поэлементно. Остальное выводится на месте:

- `bezier` — из `node.routing`, это проп, подписка не нужна;
- касательные — из самих точек: первый и последний сегменты.

Ирония замечена верно: план чинил ложную запись механизмом, который её
не чинит.

## 2. Срез шага 5 и шага 4 — одна точка, не две

Проверил: `TextStyleRows` в инспекторе не содержит поля значения, и это
намеренно. Значит «подпись только для чтения из инспектора» читать неоткуда:
без ввода `label.value` навсегда пустой, и шаг 4 не рисует ничего.

**Решение:** срез 5 и 4 объединён в один пункт. Формулировка «остаётся
для чтения» из плана убрана как неверная.

## 3. Ветка «спиной к спине» (`left`→`right`) — принято

Замечание ревьюера геометрии действительно пропало из плана молча.
Попадает в ту же ветку, что и «лицом к лицу», и разрез посередине уводит
маршрут сквозь собственную фигуру.

## 4. Сонаправленные стороны при равной высоте — принято, алгоритм переписан

Проверка права: при `s1.y == s2.y` поперечный сегмент нулевой, линия идёт
насквозь через дальнюю фигуру, а критерий «все сегменты ортогональны»
это пропускает.

**Новый алгоритм ветки:** сначала поперёк, потом вдоль, потом обратно —
`p1 → s1 → (s1.x, Y) → (s2.x, Y) → s2 → p2`, где `Y` вынесен за
объединяющую рамку **двух связанных фигур** плюс вылет, в ближнюю сторону.

**Явная граница:** обходятся только две фигуры, которые эта линия соединяет.
Третьи фигуры не обходятся — это `A*`-роутинг, он вне ТЗ. Записано
как ограничение, а не как недоделка.

# Итоговый алгоритм ломаной

Обозначения: `p` — точка якоря, `d` — внешняя нормаль стороны,
`s = p + d * stub` — конец вылета.

| Условие | Маршрут |
|---|---|
| оси разные (перпендикулярно) | одна точка перегиба на пересечении лучей |
| одна ось, нормали навстречу друг другу | разрез посередине между вылетами |
| одна ось, нормали сонаправлены **или** врозь | поперёк за объединяющую рамку, вдоль, обратно |
| дистанция меньше 1e-6 | прямая из двух точек |

У свободных концов нормаль выводится из направления на противоположный
конец по доминирующей оси — тем же правилом, что `autoAnchor`.

# Порядок и точки среза — исправленный

1. `routing.ts` + тесты — **не режется**
2. `labelPosition.ts` + тесты — не режется, переживает срез кривой
3. `ConnectorView`: подписка (`number[]`), маршрут, наконечники — **не режется**
4. Подпись: отрисовка **и** ввод — **режется целиком, одним куском**
5. Кривая — режется, но только до написания её тестов

Тесты в срез не входят ни на одном шаге: ортогональность ломаной глазами
не проверяется.
