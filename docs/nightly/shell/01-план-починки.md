### Что проверялось и не сломалось

Синтаксис импорта (пустой файл, мусор, обрезанный JSON, массив, `null`, строка,
число, чужой `format`, NUL внутри строки, BOM); все восемь вариантов чужой
версии схемы; отмена и возврат (Cmd+Z сразу после загрузки, сразу после импорта,
после смены проекта — везде чисто); экспорт пустой доски; предел PNG 16384;
инвариант 4 при удалении узла с привязанным коннектором; XSS через имя проекта,
`fill` и `stroke`; прототипное загрязнение через `__proto__` как id узла
(`Object.prototype` не портится, но узел исчезает — это подвид П1);
производительность импорта (20 000 узлов, 3.6 МБ — 365 мс); картинка-бомба
40 МБ; двойные клики в диалогах; быстрое переключение маршрутов.

## Развилка, которую надо решить до кода

**Чинить или отказывать?** Два входа документа ведут себя по-разному:

- **Импорт файла** — чужие данные, отказ допустим и уже так работает.
- **Чтение из IndexedDB** — данные пользователя, и часть из них **уже испорчена**
  сегодняшним багом. Отказ здесь означает «твоя доска больше не открывается».

Решение: **чинить всё, что чинится однозначно, и говорить об этом; отказывать
только там, где починка была бы гаданием.** Один и тот же код на обоих входах —
тогда чтение из базы задним числом лечит доски, испорченные до фикса.

| Нарушение | Решение | Почему |
|---|---|---|
| `zoom` вне `[0.1, 4]` | зажать | однозначно |
| дубли в `order` | оставить первое вхождение | однозначно |
| id в `order` без узла | выкинуть из `order` | уже так делает `removeNode` |
| узел без записи в `order` | дописать в конец | однозначно |
| `opacity` вне `[0, 1]` | зажать | однозначно |
| `width`/`height` ≤ 0 или не конечные | к `1` | однозначно |
| `x`/`y`/`rotation` не конечные | к `0` | однозначно |
| `Endpoint` с `nodeId` **и** `point` | оставить `nodeId` | привязка сильнее координаты |
| `Endpoint` пустой `{}` | к `point: {x:0, y:0}` | иначе линию не нарисовать |
| `Endpoint.nodeId` в несуществующий узел | отвязать через `operations.removeNode` | инвариант 4 это уже умеет |
| `group.children` с чужими id | выкинуть лишние | однозначно |
| ключ в `nodes` ≠ `node.id` | **отказ** | неясно, что правда — ключ или поле |
| `schemaVersion` чужой | **отказ** | уже так работает |

Починку на импорте показывать тостом: «Доска открыта, но 3 места пришлось
поправить: …». Молча чинить чужой файл нельзя — человек должен знать, что
получил не то, что отдавали.

**Это решение записать в `docs/DECISIONS.md`.**

## Фаза 1 · Критичное

### 1.1 Санитайзер документа — ядро всего плана

**Закрывает П1**, а заодно `anchor: 'centre'` из

Новый файл `src/features/persistence/repair.ts` (зона B):

```ts
export interface Repair { rule: 1 | 2 | 3 | 4 | 5; what: string }
export function repairDocument(doc: BoardDocument): {
  document: BoardDocument;
  repairs: Repair[];
}
```

Чистая функция, без React и без стора — тестируется vitest'ом напрямую.

Вызывается в двух местах:

- `features/export/model/transfer.ts` → `importJson`, после `parseBoardFile`,

- `app/CanvasScreen.tsx` → сразу после `getDocument`, до `loadDocument`. Если
  `repairs.length > 0` — записать починенный документ обратно через
  `saveDocument`, иначе он будет чиниться при каждом открытии.

Плюс ужесточить схему в `features/export/lib/fileFormat.ts` там, где отказ
правильнее починки: ключ ≠ `node.id`, нечисловые координаты. Файл для этого
и заведён — его docstring прямо говорит, что схема живёт в зоне B намеренно.

**Почему не `shared/model/invariants.ts`:** его шапка говорит «Реализуются
в зоне A». Лезть туда — нарушить правило зон. См. фазу 4.

**Проверка:** все кейсы из И3 дают либо отказ, либо починенный документ; И15.2

### 1.2 Сборка мусора по картинкам

**Закрывает П2.**

В `features/persistence/blobStore.ts`:

```ts
/** blobId, на которые не ссылается ни один документ. */
export const collectOrphanBlobs = async (): Promise<Id[]>
export const sweepBlobs = async (): Promise<number>
```

**Важная тонкость: не удалять блоб при `removeNodes`.** Узел вернётся по Cmd+Z,
а картинка уже стёрта — отмена превратится в дыру. Чистим только по факту, что
на блоб не ссылается ни один *документ*:

- в `deleteProject` — собрать `blobId` удаляемого документа, после коммита
  транзакции снести те, которых нет в других документах;
- `sweepBlobs()` один раз при старте приложения — подметает то, что натекло
  раньше, включая сирот от неудачных импортов;
- в `importJson` — `try/catch` вокруг цикла `putImage`: при отказе снести уже
  записанные блобы, тогда И8.3 перестанет копить копии при повторных попытках.

Заодно вызвать `releaseImageCache()` в cleanup-эффекте `CanvasScreen` — её
docstring просит звать при выходе с холста, но никто не зовёт.

**Проверка:** `e2e/blobs-gc.spec.ts` — импорт трёх картинок, удаление проекта,
`blobs` пуст; удаление узла-картинки — блоб **на месте**; Cmd+Z — картинка
рисуется.

### 1.3 Две вкладки перестают врать

**Закрывает П3 и П4.** Без изменения контракта, только `features/persistence`.

1. **Обнаружение чужой записи.** В `autosave.ts` запомнить `updatedAt` проекта
   на момент загрузки. В `saveDocument` внутри транзакции сверить: если в базе
   `updatedAt` больше запомненного — документ изменила другая вкладка, писать
   нельзя.
2. **Что делать при конфликте.** Не перетирать. Индикатор переводится
   в состояние `conflict`, тост: «Доска изменена в другой вкладке. Обновите
   страницу — иначе ваши правки не сохранятся». Никакого автоматического
   слияния — это не задача на вечер.
3. **Проект исчез.** `saveDocument` сейчас пишет документ, даже когда
   `project === undefined`. Изменить: нет проекта — не писать документ вообще,
   вернуть признак, индикатор в `deleted`, тост «Проект удалён». Это убирает
   документы-сироты в корне.
4. **`BroadcastChannel('prostor')`** — вкладка, записавшая документ или
   удалившая проект, шлёт сообщение; вкладки с тем же `projectId` реагируют
   сразу, а не при следующей попытке записи. Экран списка по этому же каналу
   дёргает `bumpRevision()` — заодно чинит устаревший список.

`SaveStatus` в `autosave.ts` расширяется:
`'idle' | 'saving' | 'saved' | 'error' | 'conflict' | 'deleted'`,
`SaveIndicator` — соответственно.

**Проверка:** И13.1 — вкладка A видит конфликт, её узел не исчезает молча;
И7.1 — `documents` не остаётся без `projects`.

### 2.3 Разнотипное выделение перестаёт затирать значения одним кликом

**Закрывает П7.**

`ColorField` — когда `value === undefined` («разные»), не отдавать `onChange`
наружу до **явного** подтверждения: палитра и `HexColorInput` работают
с локальным черновиком, под палитрой появляется кнопка «Применить ко всем (3)».

Это ровно та «Применить», которую docstring `ColorField` запрещает — но запрет
писался для **однородного** выделения, где цвет один и тянуть его за курсором
правильно. Для «разные» правило обратное: там нечего вести за курсором, там есть
что потерять. Условие — `value === undefined`, в остальных случаях поведение
не меняется.

`SliderField` — при `value === undefined` бегунок стоит на `min` и врёт. Не
рисовать бегунок вовсе, оставить «—» и подпись. Второй вариант — ставить
посередине с приглушением и игнорировать одиночный клик по дорожке, но первый
проще и не врёт.

## Фаза 4 · Что уходит напарнику

Записать в `docs/CONTRACT-REQUESTS.md` по образцу из файла, `B → A`:

1. **`shared/model/invariants.ts`** — реализовать по шапке файла («реализуются
   в зоне A»), чтобы 13 тестов позеленели. Когда будет готово, зона B переключит
   `repair.ts` с собственных проверок на `validateDocument()` и оставит у себя
   только починку. До тех пор — временная дубликация, и это надо назвать вслух
   в коммите.
2. **`moveNodes`/`resizeNode` для `group`** — должны двигать и `children`.
   Сейчас инспектор двигает рамку, дети остаются (П10). До ответа зона B прячет
   поля геометрии у групп.
3. **`opacity` вне `[0, 1]` роняет отрисовку**: `InvalidStateError: drawImage …
   width or height of 0` на каждом кадре (И15.1). Санитайзер закроет это
   на входе, но зажать в `updateNode` на стороне A всё равно стоит — панель
   не единственный источник.

Если зоны A и B сейчас на самом деле один человек — пункты 1 и 2 переезжают
в фазы 1 и 3 соответственно, но коммит на `shared/store` всё равно с префиксом
`contract:`.
