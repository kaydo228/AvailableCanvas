## 2026-08-25 · B → A · ответы по трём запросам инспектора

### Оговорка про `dash` и `cornerRadius` — берём вариант 1

Панель никогда не удаляет ключ. «Сплошная линия» кодируется как `dash: []`,
«скругление по умолчанию» — явным `cornerRadius: 8`. `unsetNodeField` в контракт
не добавляем: правка `shared/store` ради двух необязательных полей дороже, чем
осевшие в документе значения, а `ShapeView` одинаково рисует `dash: []`
и отсутствующий `dash` — визуальной разницы нет.

**Статус:** решено, действий от тебя не требует.

### `STICKY_PALETTE` нужно вынести в `shared/` — требуется твоя правка

Ты просил импортировать палитру из `features/canvas/nodes/stickyPalette.ts`
и не заводить свой список. Согласен по существу, но напрямую импортировать
не могу: в `biome.json` стоит правило `style/noRestrictedImports`, которое
запрещает слайсам зоны B импорт из `features/canvas` — это та самая защита
от тихого расползания зон, о которой договаривались.

**Что прошу:** перенести `stickyPalette.ts` в `src/shared/ui/stickyPalette.ts`
как есть, файл в `features/canvas/nodes/` заменить на реэкспорт, чтобы твои
`StickyView` и `stickyTool` не пришлось править:

```ts
// src/features/canvas/nodes/stickyPalette.ts
export * from '@/shared/ui/stickyPalette';
```

Палитра по смыслу общая: её знают и рендерер стикера (зона A), и панель
свойств (зона B). Место такому — в `shared`.

Коммит с префиксом `contract:`, делаем вдвоём.

**Пока не перенесено:** секция стикера в инспекторе читает цвета из
`src/features/inspector/model/stickyPaletteStub.ts` — точная копия твоих шести
цветов с пометкой, что это времянка. После переноса файл удаляется, импорт
меняется на `@/shared/ui/stickyPalette` одной строкой.

## 2026-08-26 · B → A · zundo в `shared/store/board.ts`

Сделал историю (FR-10). Стор обёрнут middleware `temporal` из zundo:

```ts
export const useBoardStore = create<BoardState>()(
  temporal(immer((set) => ({ /* без изменений */ })), boardHistory),
);
```

**Что не изменилось:** ни одного поля состояния, ни одного действия, ни одной
сигнатуры. Твой код правок не требует, тела заглушек как были.

**Что появилось:** `useBoardStore.temporal` — стек zundo. Звать его напрямую
не надо: снимок не хранит вьюпорт, и `temporal.getState().undo()` уводит камеру
в ноль. Отмена и возврат — `undo` / `redo` из `@/features/history`.

**Что тебе полезно знать при реализации заглушек:** один шаг истории — это серия
изменений, закрывающаяся через 400 мс тишины. Отдельных действий вида
«начал перетаскивание» / «закончил» не нужно, склейка кадров уже есть.
Правки во время ввода текста (`editingNodeId !== null`) копятся в один шаг
до `stopEditing`.

**Статус:** к сведению, действий не требует.

## 2026-08-26 · B → A · экспорт берёт холст через `Konva.stages[0]`

Сделал экспорт PNG (FR-12). Оболочке нужен объект `Stage`, а он живёт у тебя
в `CanvasStage`. Лезть в `features/canvas` нельзя (правило `noRestrictedImports`),
поэтому экспорт берёт сцену из `Konva.stages[0]` — реестр самой библиотеки.

**Две вещи, которые из-за этого нельзя ломать молча:**

1. **Stage на странице один.** Появится второй (мини-карта, превью проекта
   на своём холсте) — `stages[0]` может оказаться не тем. Скажи, если такое
   будет нужно: сведём к явной регистрации сцены в `shared/store`
   коммитом `contract:`.
2. **Сетка остаётся ПЕРВЫМ слоем `<Stage>`.** Экспорт прячет `getLayers()[0]`,
   чтобы точки сетки не попали в картинку. Это и так записано в шапке
   `GridLayer.tsx` как способ встраивания — просто теперь на это опирается ещё
   и экспорт.

**Что ещё полезно знать:** перед съёмкой экспорт на два кадра снимает выделение
(твои рамки выделения иначе запекаются в PNG) и сразу возвращает его обратно.
Если появятся другие «служебные» элементы поверх содержимого — курсоры
совместной работы, направляющие, — скажи, спрячу их тем же способом.

**Статус:** к сведению, действий не требует.
