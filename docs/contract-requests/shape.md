# 2026-08-25 · A → B · узел `shape` (фигура)

Тип `ShapeNode` уже в союзе `Node` (`src/shared/types/document.ts`), новых правок
`shared/types` от инструмента не потребовалось.

**Поля:** `id`, `type: 'shape'`, `shape: 'rect' | 'roundRect' | 'ellipse' |
'triangle' | 'diamond'`, `x`, `y`, `width`, `height`, `rotation`, `opacity`,
`locked`, `groupId?` (всё из `BaseNode`), плюс `fill`, `stroke`, `strokeWidth`,
`dash?`, `cornerRadius?`, `label?: TextStyle`.

## Что нужно в инспекторе

| Поле | Элемент управления | Примечание |
|---|---|---|
| `shape` | сегментированный переключатель из пяти иконок | смена формы не меняет рамку: `x/y/width/height` остаются как были |
| `fill` | цвет + палитра пресетов | по умолчанию `#ffffff` |
| `stroke` | цвет | по умолчанию `#111111` |
| `strokeWidth` | число, шаг 1, диапазон 0–20 | `0` = без обводки, это валидное состояние |
| `dash` | выбор из «сплошная / пунктир / штрих» | поле **необязательное**: «сплошная» — это отсутствие `dash`, а не `dash: []`. Из-за `exactOptionalPropertyTypes` присвоить `undefined` нельзя, нужен патч-удаление (см. ниже) |
| `cornerRadius` | число, только при `shape === 'roundRect'` | если не задано, рендерер берёт `8` (`DEFAULT_CORNER_RADIUS` в `nodes/ShapeView.tsx`). Плейсхолдер поля лучше показывать как `8` |
| `opacity` | ползунок 0–100 % | в модели 0..1, не проценты |
| `rotation` | число, градусы | |
| `x`, `y`, `width`, `height` | четыре числовых поля | мировые единицы; отрицательные `width/height` инструмент не создаёт, но и инспектор их пускать не должен |
| `locked` | переключатель | при `locked: true` рендерер снимает `draggable` |
| `label.value` | не в инспекторе | подпись правится по двойному клику на холсте через `TextOverlay`, дублировать её текстовым полем в панели не нужно |
| `label.fontSize`, `label.color`, `label.align`, `label.bold`, `label.italic`, `label.lineHeight` | как у текстового узла | показывать секцию «Подпись», только когда `label` задан; если подписи ещё нет — кнопка «Добавить подпись», которая шлёт целый объект `TextStyle` |

## Общее с другими типами при множественном выделении

Показывать общими полями (одинаковый смысл у фигуры, текста, стикера, картинки,
рисунка и группы):

- `x`, `y`, `width`, `height`, `rotation`, `opacity`, `locked` — весь `BaseNode`;
- операции порядка слоёв и группировки.

Общее с частью типов:

- `fill` — общий со стикером (`StickyNode.fill`), но **не** с текстом и картинкой;
- `stroke`, `strokeWidth`, `dash` — общие с коннектором (`ConnectorNode`)
  и с рисунком (`DrawNode`, у него нет `dash`);
- секция «Подпись/Текст» — общая по типу `TextStyle` с текстом (`text`),
  стикером (`text`) и коннектором (`label`), но поле называется по-разному:
  у фигуры и коннектора это `label`, у текста и стикера — `text`. Панели
  придётся смотреть на `type`, одним ключом не обойтись.

Не общее и должно скрываться при разнотипном выделении: `shape`, `cornerRadius`.

## Действия стора

Панель зовёт `updateNode(id, patch)` и `updateNodes(ids, patch)` — их хватает.
**Новых действий не требуется**, с одной оговоркой.

**Оговорка про `dash` и `cornerRadius`.** Это необязательные поля, и «вернуть
к значению по умолчанию» = удалить ключ, а не записать `undefined`.
Сейчас `updateNode` делает `Object.assign(node, patch)`, а `NodePatch` собран
как `Partial<DistributiveOmit<Node, 'id' | 'type'>>` — записать `undefined`
типы не дадут, а удалить ключ нечем. Варианта два, выбери и скажи:

1. панель никогда не удаляет ключ: «сплошная линия» кодируется как `dash: []`,
   «скругление по умолчанию» — как `cornerRadius: 8` явным числом.
   Ничего менять не надо, но в документе оседают значения, которых
   пользователь не задавал;
2. добавляем в контракт `unsetNodeField(ids, field)` — правка `shared/store`,
   делаем вдвоём коммитом `contract:`.

Мне ближе первый: рендерер `ShapeView` одинаково рисует и `dash: []`,
и отсутствующий `dash`, так что визуальной разницы нет.
