# Игровой диздок на свободном канвасе

Пользователь утвердил направление для соло/инди-команды и попросил реализовать все три предложенных этапа, исправить стрелку и запушить результат. Это рабочая спецификация исполнения; дополнительные согласования не требуются.

## Поведение

1. Стрелка P создаёт связь объектов, а не свободный рисунок. Новые связи ортогональные, обходят контент, пересчитываются при перемещении, показывают реальный маршрут при создании. Существующие рисунки сохраняются.
2. Карточки: концепт, механика, персонаж, противник, предмет, ресурс, локация, квест, плейтест. Краткая карточка на канвасе, полное редактирование в панели. Поля необязательные, стикер превращается в карточку без потери id/связей. Статус проверки отдельно от реализации.
3. Именованные секции с составом, оглавлением, сворачиванием, порядком чтения. Рамка меняет размер без масштабирования содержимого. Содержимое редактируется обычным кликом. Перемещение секции переносит состав.
4. Поиск по тексту карточек/секций/старых заметок, фильтры тип/статус/теги, переход камеры. Ссылка на объект через query node; представление-ссылка хранит targetId, не копию данных. Недоступная цель показана явно.
5. Шаблоны: концепт, основной цикл, механика, противник, уровень, квест, плейтест. Вставляются обычными редактируемыми объектами без принудительного заполнения.
6. Смысловые коннекторы: требует, расходует, даёт, открывает, переходит в, связано с. В карточке отображаются входящие/исходящие связи и ссылки/обратные ссылки.
7. Режим чтения по порядку секций и экспорт Markdown из тех же данных, без второй копии документа.
8. Плейтест как карточка с гипотезой, сценарием, наблюдениями и решением; связи с проверяемыми карточками. Таблица параметров с редактируемыми колонками/строками. Комментарии с указанным автором, временем и состоянием решения.
9. Именованные версии: снимки узлов/порядка/фона без рекурсивного вложения версий. Просмотр/восстановление с подтверждением и сохранением страховочного снимка; снимки сохраняются и экспортируются, их картинки не теряются.

## Архитектура

React/Konva, текущий Zustand/Immer, без новых зависимостей. Карточки и секции — специализированные shape-узлы с optional design; связь — существующий connector с optional relation. Это сохраняет общий контракт геометрии и обратное чтение старых досок. Формат расширяется аддитивно; импорт и clipboard должны сохранять и проверять новые поля.

Секции не GroupNode: собственный список children, без вложенных секций. Дублирование секции копирует состав и перевязывает внутренние ссылки. Удаление секции оставляет содержание. Скрытое содержимое нельзя случайно выбрать рамкой. Ссылка на карточку ведёт на оригинал; копия карточки независима.

UI продолжает текущую спокойную визуальную систему, русские названия, доступные подписи полей и кнопок. Панели расположены вне канваса; сами узлы рисует Konva.

## Проверки

Юнит-тесты геометрии стрелок и данных диздока; round-trip JSON/clipboard, копирование, удаление, восстановление версии; UI-сценарий создания, редактирования, поиска и чтения; общие typecheck/lint/unit/e2e и performance. Пользовательские незакоммиченные sessions-файлы не включать в коммит.
