# 1. Цель и границы

## 1.1. Что делаем

Веб-приложение «бесконечная доска»: пользователь создаёт проект и получает свободный
холст, на котором размещает фигуры, текст, стикеры, изображения и соединяет их линиями.
Всё размещённое можно свободно перемещать, изменять и удалять.

Референс по духу — FigJam. **Референс, а не цель:** воспроизводится механика свободного
холста, а не объём продукта.

## 1.2. Чего НЕ делаем

Явно вне границ, чтобы не расползлось:

- аккаунты, авторизация, серверная часть — приложение полностью клиентское;
- совместное редактирование в реальном времени (вынесено в «может быть», п. 4.3);
- мобильная вёрстка и тач-жесты — целевое устройство десктоп с мышью;
- импорт из Figma/Miro, плагины, комментарии-треды, история версий;
- печать и вывод в PDF.

## 1.3. Ограничения

| Параметр | Значение |
|---|---|
| Срок | 29 августа 2026, 18:00 |
| Команда | 2 фронтенд-разработчика |
| Бэкенд | отсутствует, данные в браузере |
| Целевой браузер | Chrome/Safari последних версий, десктоп |

# 2. Роли и разделение работы

Два разработчика, два непересекающихся слоя. Шов между ними — типы данных и стор,
зафиксированные в первый день.

| | Разработчик A — «Движок» | Разработчик B — «Оболочка» |
|---|---|---|
| Зона | всё, что рисуется на холсте | всё, что вокруг холста |
| Модули | `canvas/engine`, `canvas/nodes`, `canvas/tools`, `canvas/selection`, `canvas/connectors` | `projects`, `inspector`, `history`, `persistence`, `export`, `shortcuts` |
| Отвечает за | координаты, рендер, hit-test, трансформации, привязку линий | список проектов, панель свойств, сохранение, undo/redo, экспорт |
| Не трогает | ничего вне `features/canvas` | ничего внутри `features/canvas` |

**Контракт между зонами** (фиксируется в день 1, дальше меняется только по договорённости
обоих): `shared/types/document.ts` — модель данных, и `shared/store` — набор действий над
документом. B вызывает действия, A их исполняет и рисует. Пересечение по файлам почти
нулевое, конфликты при merge — только в `store` и в типах.

# 3. Стек

| Слой | Решение | Почему |
|---|---|---|
| Каркас | React 19 + TypeScript + Vite | быстрый старт, знакомо обоим |
| Рендер холста | **react-konva** (Canvas 2D) | даёт hit-test, трансформер и перетаскивание из коробки; DOM/SVG не тянет тысячу узлов |
| Состояние | Zustand + Immer | плоский стор, простые действия, дешёвый undo/redo |
| Хранение | IndexedDB через `idb` | нужно хранить изображения как blob, localStorage их не потянет |
| Стили | CSS Modules или Tailwind — на усмотрение B | вкусовщина, на результат не влияет |
| Тесты | Vitest (модель, роутинг линий, история) + Playwright (2–3 сценария) | Playwright заодно закрывает бонус ДЗ по агенту-ломателю |

**Почему не tldraw/excalidraw:** это готовые доски целиком, брать их — значит сдать чужой
продукт. Konva — библиотека рендера, аналог того, как в реальном проекте берут WebGL-обёртку.

# 4. Функциональные требования

Приоритеты: **MUST** — без этого работа не сдаётся, **SHOULD** — делаем, если MUST закрыт
к четвергу, **COULD** — только если всё остальное готово.

## 4.1. MUST — минимально работающий продукт

### FR-01. Проекты и пустое состояние

- При первом входе показывается пустое состояние: заголовок, пояснение и кнопка
  «Создать проект». Никаких пустых серых списков.
- Кнопка открывает диалог с полем имени; по умолчанию — «Новый проект».
- После создания пользователь **сразу попадает на холст** этого проекта.
- При наличии проектов показывается сетка карточек: превью, имя, дата изменения.
- Карточка: открыть по клику, контекстное меню — переименовать, дублировать, удалить.
- Удаление — с подтверждением, потому что необратимо.
- Маршруты: `/` — список, `/p/:projectId` — холст. Перезагрузка страницы на холсте
  открывает тот же проект в том же положении вида.

### FR-02. Холст и навигация

- Бесконечное полотно, координаты мировые, вид задаётся `{x, y, zoom}`.
- Панорамирование: колесо/трекпад, `Space` + перетаскивание, средняя кнопка мыши.
- Зум: `Cmd/Ctrl` + колесо — **к позиции курсора**, не к центру экрана.
- Диапазон зума 10 %–400 %, индикатор в углу, клик по нему — меню `50 / 100 / 200 %`,
  «Вписать всё» (`Cmd+1`), «Вписать выделенное» (`Cmd+2`), «100 %» (`Cmd+0`).
- Фоновая сетка из точек, плотность зависит от зума, на мелком зуме скрывается.

### FR-03. Фигуры

- Набор MVP: прямоугольник, скруглённый прямоугольник, эллипс, треугольник, ромб.
- Создание: выбрать инструмент → протянуть на холсте. Клик без протяжки создаёт фигуру
  размера по умолчанию.
- `Shift` при создании и при изменении размера сохраняет пропорции.
- **У любой фигуры есть внутренняя подпись**: двойной клик входит в редактирование текста,
  текст центрируется и переносится по ширине. Это то, что делает фигуры пригодными
  для диаграмм.
- Свойства: заливка, цвет и толщина обводки, пунктир, скругление, прозрачность.

### FR-04. Текст

- Инструмент «Текст»: клик — точка вставки, протяжка — блок фиксированной ширины.
- Редактирование по месту, двойной клик по существующему тексту.
- Свойства: размер, цвет, жирный, курсив, выравнивание, межстрочный интервал.
- Пустой текстовый блок при потере фокуса удаляется сам.

### FR-05. Стикеры

- Квадратная заметка с заливкой и текстом, палитра из 6 цветов.
- Текст автоматически уменьшается, если не помещается (до минимального кегля, дальше скролл).
- Двойной клик по пустому месту холста при активном инструменте создаёт стикер сразу
  в режиме ввода — самый частый сценарий, он должен быть в один жест.

### FR-06. Изображения

- Загрузка тремя способами: кнопка на панели, перетаскивание файла на холст, вставка
  из буфера (`Cmd+V`).
- Форматы PNG, JPEG, GIF, SVG, WebP. Лимит 10 МБ на файл, при превышении — понятная ошибка.
- Файл кладётся в IndexedDB как blob, в документе хранится только идентификатор.
- Вставляется с сохранением пропорций, вписывается в 600 px по большей стороне.
- Изменение размера с сохранением пропорций, `Shift` — свободное.

### FR-07. Линии и соединители

Ключевой и самый трудоёмкий пункт. Разделяется на два поведения:

**Свободная линия** — оба конца в произвольных точках холста.

**Соединитель** — конец привязан к фигуре. При наведении инструмента на фигуру
подсвечиваются четыре якоря (верх, право, низ, лево). При перемещении или изменении
размера привязанной фигуры линия **пересчитывается автоматически**.

- Типы прокладки: прямая, ломаная под прямым углом (elbow), кривая Безье.
- Наконечники независимо на каждом конце: нет, стрелка, точка.
- Стиль: цвет, толщина, пунктир.
- Подпись на линии по двойному клику, размещается в середине.
- При удалении фигуры привязанные к ней концы линий **отвязываются и остаются на месте**,
  сами линии не удаляются.

### FR-08. Выделение и трансформации

- Клик — выделить, `Shift`+клик — добавить в выделение, клик по пустому — снять.
- Рамка выделения по протяжке инструментом «Выбор» на пустом месте.
- Ручки трансформера: 8 для размера, отдельная для поворота.
- Перетаскивание одного объекта или группы выделенных.
- Стрелки — сдвиг на 1 px, `Shift`+стрелки — на 10 px.
- `Delete`/`Backspace` — удалить, `Cmd+A` — выделить всё.
- Порядок слоёв: `]` вперёд, `[` назад, `Cmd+]` / `Cmd+[` — в самый верх/низ.

### FR-09. Панель свойств

- Правая панель, содержимое зависит от типа выделенного объекта.
- При множественном выделении показываются общие свойства; изменение применяется ко всем.
- Пустое выделение — панель показывает свойства холста (цвет фона, сетка).
- Изменение цвета применяется мгновенно, без кнопки «Применить».

### FR-10. История

- `Cmd+Z` / `Shift+Cmd+Z`, глубина не менее 50 шагов.
- Одно действие пользователя = один шаг. Перетаскивание — один шаг на всё перемещение,
  а не на каждый кадр. Ввод текста — один шаг на сессию редактирования.
- История своя у каждого проекта, при выходе из проекта сбрасывается.

### FR-11. Сохранение

- Автосохранение в IndexedDB, дебаунс 500 мс после последнего изменения.
- Индикатор состояния: «Все изменения сохранены» / «Сохранение…».
- Сохраняется в том числе положение вида — при возврате в проект пользователь видит
  то же, что оставил.
- Превью проекта перерисовывается при выходе из холста.

### FR-12. Экспорт

- PNG всей доски или выделенного фрагмента, множитель 1× / 2×.
- JSON — полный документ вместе с изображениями в base64, для переноса между машинами.

# 5. Модель данных

```ts
type Id = string;

interface Project {
  id: Id;
  name: string;
  createdAt: number;
  updatedAt: number;
  thumbnail?: string;          // dataURL, обновляется при выходе из проекта
}

interface BoardDocument {
  projectId: Id;
  schemaVersion: 1;            // для миграций при смене формата
  nodes: Record<Id, Node>;
  order: Id[];                 // порядок отрисовки снизу вверх
  viewport: Viewport;
  background: { color: string; grid: 'dots' | 'lines' | 'none' };
}

interface Viewport { x: number; y: number; zoom: number }

type Node =
  | ShapeNode | TextNode | StickyNode | ImageNode | ConnectorNode | DrawNode | GroupNode;

interface BaseNode {
  id: Id;
  x: number; y: number;        // мировые координаты левого верхнего угла
  width: number; height: number;
  rotation: number;            // градусы
  opacity: number;             // 0..1
  locked: boolean;
  groupId?: Id;
}

interface TextStyle {
  value: string;
  fontSize: number;
  color: string;
  align: 'left' | 'center' | 'right';
  bold?: boolean;
  italic?: boolean;
  lineHeight?: number;
}

interface ShapeNode extends BaseNode {
  type: 'shape';
  shape: 'rect' | 'roundRect' | 'ellipse' | 'triangle' | 'diamond';
  fill: string;
  stroke: string;
  strokeWidth: number;
  dash?: number[];
  cornerRadius?: number;
  label?: TextStyle;           // подпись внутри фигуры
}

interface TextNode extends BaseNode { type: 'text'; text: TextStyle; autoWidth: boolean }

interface StickyNode extends BaseNode { type: 'sticky'; fill: string; text: TextStyle }

interface ImageNode extends BaseNode {
  type: 'image';
  blobId: Id;                  // ключ в IndexedDB, не сам файл
  naturalWidth: number;
  naturalHeight: number;
}

interface DrawNode extends BaseNode {
  type: 'draw';
  points: number[];            // [x1,y1,x2,y2,...] в локальных координатах
  stroke: string;
  strokeWidth: number;
}

interface GroupNode extends BaseNode { type: 'group'; children: Id[] }

type Anchor = 'top' | 'right' | 'bottom' | 'left' | 'auto';

interface Endpoint {
  nodeId?: Id;                 // задан — конец привязан к фигуре
  anchor?: Anchor;             // 'auto' — сторона выбирается по взаимному положению
  point?: { x: number; y: number };  // задан — конец свободный
}

interface ConnectorNode {
  id: Id;
  type: 'connector';
  from: Endpoint;
  to: Endpoint;
  routing: 'straight' | 'elbow' | 'curve';
  stroke: string;
  strokeWidth: number;
  dash?: number[];
  startCap: 'none' | 'arrow' | 'dot';
  endCap: 'none' | 'arrow' | 'dot';
  label?: TextStyle;
  locked: boolean;
  opacity: number;
}
```

**Инварианты модели** (проверяются юнит-тестами):

1. Каждый `id` из `order` существует в `nodes`, и наоборот — соответствие взаимно однозначное.
2. `ConnectorNode` не участвует в `groupId`.
3. У `Endpoint` задан ровно один из `nodeId` или `point`, никогда оба и никогда ни одного.
4. Удаление узла обязано отвязать все ссылающиеся на него `Endpoint`, подставив им
   последние вычисленные координаты в `point`.
5. `zoom` всегда в диапазоне `[0.1, 4]`.

# 6. Интерфейс

## 6.1. Экраны

**Список проектов.** Шапка с названием приложения и кнопкой «Создать проект». Сетка
карточек. Пустое состояние вместо пустой сетки.

**Холст.** Шапка: назад к списку, имя проекта с переименованием по клику, индикатор
сохранения, экспорт. Слева вертикальная панель инструментов. Справа панель свойств,
сворачиваемая. Внизу слева индикатор зума. Остальное — холст.

## 6.2. Инструменты

| Клавиша | Инструмент |
|---|---|
| `V` | Выбор |
| `H` | Рука (панорамирование) |
| `S` | Стикер |
| `T` | Текст |
| `R` | Прямоугольник |
| `O` | Эллипс |
| `D` | Ромб |
| `L` | Линия / соединитель |
| `P` | Перо *(SHOULD)* |
| `I` | Изображение |

После создания объекта инструмент **возвращается к «Выбору»**, кроме случая, когда
он зафиксирован повторным кликом по кнопке панели.

## 6.3. Горячие клавиши

| Сочетание | Действие |
|---|---|
| `Cmd+Z` / `Shift+Cmd+Z` | отменить / вернуть |
| `Cmd+C` / `Cmd+V` / `Cmd+D` | копировать / вставить / дублировать |
| `Delete` | удалить выделенное |
| `Cmd+A` | выделить всё |
| `Cmd+G` / `Shift+Cmd+G` | сгруппировать / разгруппировать |
| `Cmd+0` / `Cmd+1` / `Cmd+2` | 100 % / вписать всё / вписать выделенное |
| `]` / `[` | вперёд / назад по слоям |
| `Space` + перетаскивание | панорамирование |
| `Esc` | сбросить выделение, выйти из режима ввода |
| `?` | справка по клавишам |

# 7. Нефункциональные требования

| ID | Требование | Как проверяется |
|---|---|---|
| NFR-01 | 1000 объектов на доске: панорамирование и зум не ниже 50 fps | сценарий-генератор + вкладка Performance |
| NFR-02 | Перетаскивание объекта — без видимых рывков при 500 объектах | вручную и записью профиля |
| NFR-03 | Автосохранение не блокирует ввод: длинная задача уходит в микротаск | ввод текста во время сохранения не теряет символов |
| NFR-04 | Открытие проекта с 500 объектами — до 1 с | замер `performance.now()` |
| NFR-05 | Первая загрузка приложения — до 2 с на обычном канале | Lighthouse |
| NFR-06 | Ошибка рендера одного узла не роняет всю доску | ErrorBoundary вокруг холста |
| NFR-07 | Данные не покидают браузер: ни одного сетевого запроса после загрузки | вкладка Network пустая |

# 8. Структура репозитория

```
src/
  app/                    — маршруты, layout, темы, ErrorBoundary        [B]
  features/
    projects/             — список, создание, пустое состояние, превью   [B]
    canvas/
      engine/             — viewport, координаты, hit-test, слои         [A]
```

# 9. Разбиение на субагентов

Обязательный пункт ДЗ: работа делается субагентами, по три независимых на человека.
Зоны не пересекаются по файлам.

**Разработчик A — движок:**

1. `engine` — вид, координаты, hit-test, сетка, зум к курсору, рендер-цикл.
2. `nodes` + `selection` — рендер фигур, текста, стикеров, изображений; трансформер.
3. `connectors` — якоря, три способа прокладки, пересчёт при перемещении, отвязка при удалении.

**Разработчик B — оболочка:**

1. `projects` + `persistence` — маршруты, список, пустое состояние, IndexedDB, автосохранение.
2. `inspector` + `shortcuts` — панель свойств по типам, множественное выделение, клавиши.
3. `history` + `export` — стек команд, слияние подряд идущих операций, PNG и JSON.

**Перекрёстная проверка.** После слияния каждый запускает **агента-ломателя в отдельной
сессии на зону напарника**: A ломает оболочку, B ломает движок. Автор не бывает
независимым проверяющим. Промпт — в сопроводительных материалах, раздел 2.

# 10. Критерии приёмки

Проверяется по пунктам, каждый — да или нет.

1. `npm i && npm run dev` поднимает приложение по инструкции из `README.md` без правки файлов.
2. Чистый браузер → видно пустое состояние → создан проект → открылся холст.
3. На холст добавлены фигура, текст, стикер и изображение; каждый объект перемещается,
   меняет размер, поворачивается и удаляется.
4. Собрана диаграмма из трёх фигур с подписями внутри и двух соединителей со стрелками.
5. Одна из фигур диаграммы передвинута — **линии перестроились сами**.
6. Одна из фигур удалена — линии остались, их концы отвязались, приложение не упало.
7. `Cmd+Z` отменяет последние пять действий по одному, `Shift+Cmd+Z` возвращает.
8. Страница перезагружена — доска и положение вида восстановлены полностью.
9. Экспорт в PNG даёт файл, визуально совпадающий с доской.
10. Экспорт в JSON и импорт в новый проект дают идентичную доску, включая изображения.
11. Сгенерированы 1000 объектов — панорамирование остаётся плавным (NFR-01).
12. Вкладка Network после загрузки пуста — данные никуда не уходят.

# 12. Риски

| Риск | Вероятность | Что делаем |
|---|---|---|
| Соединители съедают больше дня | высокая | начать с прямой линии и `anchor: 'auto'`; ломаная и Безье — отдельными шагами, каждый можно не делать |
| Расхождение по контракту типов | средняя | контракт правится только парой, изменение — отдельным коммитом с пометкой `contract:` |
| Тормоза при большом числе узлов | средняя | отдельный слой Konva для статики и для выделения; кэширование узлов, не перерисовывать неизменившиеся |
| Изображения раздувают хранилище | низкая | лимит 10 МБ, blob в IndexedDB, в документе только идентификатор |
| Реалтайм (FR-34) утаскивает время | высокая, если начать | решение о старте — только вечером четверга и только при закрытых MUST и SHOULD |
